## Patch completion hypothesis

- [ ] After the seeded V5/Patchsmith 53-task comparison and paired unseen holdout, consider a one-sentence, prompt-only patch-completion ablation on `fastapi_15589`, `rich_3061`, `rich_3938`, `rich_4075`, `rich_3468`, and `rich_3506`, using the same 31B model, request seed 42, tools, and 28-call/eight-minute budget; run only if quota remains after protecting the final-submission buffer. In the unseeded V5/reference-v2 44-task pair, V5 failed on all six and submitted only reproduction files without implementation changes. Reference-v2 resolved `fastapi_15589` and `rich_3506`, but also failed the other four. The same-ID V5 40-call run resolved `fastapi_15589`, but still failed all five Rich tasks; it edited product files on `rich_3061`, `rich_3938`, and `rich_3468`, while `rich_3506` timed out. This shows that a product-file edit alone is not a solve signal, and that extra calls did not recover a Rich pass in this sample. All six IDs are in the wheelhouse-qualified 53-task training set and outside the unseen holdout. Test whether requiring the submitted diff to implement the requested behavior (unless the task explicitly asks for a test or reproducer) prevents repro-only patches; count only changes to `resolved` as gains. Treat this as a six-task training screen, not promotion evidence, and do not promote without comparable full-suite and holdout evidence.
